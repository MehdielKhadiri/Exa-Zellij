The first CPU suite covers FBD and FBO user callbacks, all six FBD geometries,
PCA-GP/IDW/RBF/no-surrogate FBO, scalar/batch agreement, arbitrary executable
objectives, invalid configuration, nonfinite values, callback exceptions,
and unknown native objective names. Native/MPI tests also recompute the objective
at the returned coordinates, including FBD's off-centre probes and strided
float32 Python batch output. FBO tests enter the search after their initial design.
FBD's evaluation count is structural;
only FBO's Python interface imposes a user-specified evaluation cap.

The JUPITER Python bridge used Python 3.13.5, NumPy 2.3.2 and pybind11 3.0.1.
Automatic configuration also detected the site's CUDA Kokkos and compiler.
The two successful one-node jobs lasted 81 and 116 seconds, respectively,
including allocation startup/cleanup; optimizer timings are recorded separately
in their JSON results. A superseded pending job was cancelled before allocation.

Archived research results pass the existing checksum/claim verifier and are not
regenerated by these checks. Changes to external FBD scoring, MPI incumbent
coordinates and VQE error handling need consideration when comparing
new external-objective runs against older results. Backend floating-point
equivalence is numerical, not a bitwise trajectory guarantee.

The Larochette attempt ran from 00:35:47 to 00:35:49 CEST. Its scheduler stderr
reports a missing user `.bashrc`; only `exit-code.txt` (value 1) was retained in
the results directory. No environment, build, MPI-test or API-test logs were
produced. This establishes an early job setup failure, not a tested HIP compiler
or optimizer failure. The setup needs diagnosis before another validation run.

The standalone quantum simulator stack has not been rerun for this revision.
Testing the embedded Python bridge does not establish PennyLane/JAX or QPU
compatibility. AMD runtime validation and publishable Linux binary wheels remain
release gates; the repository is a development build. CI targets Linux; native
Windows validation is no longer a release requirement.
